# SOC Detection Project

## Project Overview

The SOC Detection project is a full-stack Security Operations Center (SOC) platform designed to simulate and demonstrate the day-to-day workflow of a real cybersecurity monitoring environment. The system combines security monitoring, alert detection, incident management, threat intelligence, user behavior analytics, and AI-assisted analysis into a single interactive dashboard.

The main goal of this project is to provide a practical and educational platform that shows how modern SOC operations work in real-world environments. It helps users understand how security events are collected, analyzed, correlated, and responded to using tools and techniques similar to those used in enterprise security teams.

## Problem Statement

Modern organizations face a constant flow of cyberattacks and suspicious activities. Security teams must be able to detect malicious behavior quickly, analyze events, manage incidents, respond to threats, and monitor user and system activity in real time.

However, many students and beginners do not have access to a real SOC environment for hands-on learning. There is a need for a simplified, interactive, and realistic platform that demonstrates how security monitoring and incident response work in practice.

## Objectives

- Build a realistic SOC dashboard for monitoring security alerts and incidents.
- Detect suspicious events using rule-based SIEM logic.
- Visualize security threats and attack activity in a user-friendly way.
- Manage incidents and track response activities.
- Provide threat intelligence and behavior-based detection capabilities.
- Demonstrate automation through SOAR-style workflows.
- Integrate AI-based analysis for better understanding of alerts.
- Serve as a learning and portfolio project for cybersecurity and software engineering students.

## Key Features

### 1. Real-Time SIEM Engine
The platform generates synthetic security logs and continuously detects suspicious patterns. These detections are mapped to known MITRE ATT&CK techniques and presented as alerts.

### 2. Alert and Incident Management
Security alerts are stored, categorized, and tracked. The platform allows users to review incidents, understand their timeline, and monitor overall threat activity.

### 3. Threat Intelligence
Threat intelligence modules help track malicious indicators such as suspicious domains, IPs, and attack patterns. This allows analysts to correlate alerts with external threat knowledge.

### 4. UEBA (User and Entity Behavior Analytics)
The platform analyzes user and entity behavior for anomalies. This helps identify unusual activity that may signal insider threats or compromised accounts.

### 5. SOAR Automation
SOAR playbooks support automated response steps for handling incidents efficiently. These workflows mimic security orchestration and response operations used in practical SOC environments.

### 6. Digital Forensics and Hunting
The system includes forensic analysis support and hunting workflows to investigate suspicious events and trace relevant data points.

### 7. AI Analyst Integration
An AI-driven analyst module explains alerts in human-readable language and helps users interpret complex security findings more easily.

### 8. Dashboard Interface
The frontend dashboard is built with Next.js and provides a modern visual interface for navigation, analytics, monitoring, and management operations.

## Architecture

The system follows a client-server architecture:

- The frontend is the user-facing dashboard built in Next.js.
- The backend is a FastAPI API server that processes requests and serves data.
- The SIEM engine analyzes generated logs and raises alerts.
- Alerts are communicated in real time over WebSockets.
- The database stores security data such as incidents, alerts, assets, and reports.

This design is similar to real SOC platforms where monitoring, detection, and incident response are handled by separate but connected services.

## Workflow of the Project

1. Synthetic logs are generated by the system.
2. The backend monitors and analyzes those logs.
3. Suspicious behaviors are matched against predefined detection rules.
4. Alerts are created and sent to the frontend dashboard.
5. Analysts can inspect alerts, incidents, and user activity.
6. Threat intelligence and automated responses are applied when needed.
7. Reports and investigation data are generated for review.
